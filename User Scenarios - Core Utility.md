# User Scenarios: Core Utility & Data Acquisition

This document defines the foundational user scenarios for **Monch**. These scenarios cover the **Data Acquisition Layer**—the "Input" required to power the algorithmic "Brain." The design philosophy prioritizes **Low Friction** and **Passive Collection** to ensure high data fidelity without user burnout.

---

## 1. Onboarding & Configuration
*Setting the stage for privacy-first, on-device analytics.*

### 1.1 The Permissions Handshake
*   **Scenario:** Upon first launch, the user is presented with a clear value proposition for HealthKit access.
*   **Action:** User grants read permissions for **Sleep**, **Workouts**, **Heart Rate**, **HRV**, and **Resting Energy**.
*   **Outcome:** Monch immediately backfills the last 7 days of data to establish a baseline "Metabolic Profile" (RHR, HRV trends) before the user even logs their first meal.

## 2. Nutrition Logging (The Input)
*Minimizing the "chore" of food tracking.*

### 2.1 The "Usual" Quick-Add
*   **Scenario:** It's 8:00 AM. The user opens the app to log breakfast.
*   **Action:** The app predicts their routine. User taps a single button: **"Add Daily Coffee & Oatmeal"**.
*   **Outcome:** Macros and timestamps are logged instantly. No searching required.

### 2.2 The Barcode Scan (P1 - Post MVP)
*   **Scenario:** User grabs a packaged protein bar post-workout.
*   **Action:** User taps "Scan," points the camera, and confirms the item from the Open Food Facts database.
*   **Outcome:** Precise nutritional data (including micronutrients like Magnesium/Zinc if available) is captured.
*   *Note: De-prioritized to Phase 2. Core MVP will rely on Text Search and Quick-Adds.*

### 2.3 The "Loose" Text Search
*   **Scenario:** User is eating out at a generic restaurant.
*   **Action:** User types "Grilled Chicken Salad" and selects a verified USDA average match.
*   **Outcome:** A "Good Enough" estimation is logged. Speed > Precision for general meals.

### 2.4 Stimulant & Supplement "Stack"
*   **Scenario (Caffeine):** User has an espresso at 2 PM.
*   **Action:** User taps the persistent **"Caffeine"** icon on the home screen. Logs "1 Espresso (65mg)" instantly.
*   **Scenario (Vitamins):** User takes their nightly stack.
*   **Action:** User taps **"Log Night Stack"** (pre-configured: Magnesium Glycinate, Zinc, Omega-3).
*   **Outcome:** The engine tracks specific micronutrients essential for the "Mineral Gap" insight without requiring individual pill logging every day.

## 3. Exercise Tracking (The Stressor)
*Passive capture with contextual awareness.*

### 3.1 Passive Sync (The Happy Path)
*   **Scenario:** User finishes a 5K run wearing their Apple Watch.
*   **Action:** User opens Monch 30 minutes later. The workout is already visible on the timeline ("Zone 2 Run • 35 mins").
*   **Outcome:** The engine automatically calculates the "Clearance Potential" (insulin sensitivity boost) generated by this activity.

### 3.2 Manual Override
*   **Scenario:** User played pickup basketball without a wearable.
*   **Action:** User adds "Cardio / Sport" manually, estimating duration and intensity (RPE).
*   **Outcome:** Monch estimates calorie burn and metabolic load to ensure the "Energy Balance" isn't skewed.

### 3.3 Context Inference (The "Refeed")
*   **Scenario:** User logs a high-carb meal 45 minutes after the system detected a "High Intensity" workout.
*   **Action:** *System Action Only.* The engine tags this meal as **"Post-Workout Refeed"** internally.
*   **Outcome:** The user sees this meal highlighted positively (e.g., "Fueling") rather than negatively, without needing to manually toggle a switch.

## 4. Sleep Tracking (The Recovery Baseline)
*Closing the loop on the day's choices.*

### 4.1 The Morning Review
*   **Scenario:** User wakes up and checks Monch.
*   **Action:** The "Day" view starts with a Sleep Card summarizing the previous night: **7h 12m Sleep • 15% Deep Sleep**.
*   **Outcome:** User has immediate context on their starting battery level.

### 4.2 Hypnogram Visualization
*   **Scenario:** User feels groggy.
*   **Action:** User taps the Sleep Card to see the Hypnogram (Stages graph).
*   **Outcome:** They notice a lack of Deep Sleep in the first 4 hours, hinting at a potential "Digestion Debt" (late meal) investigation.

### 4.3 Data Correction
*   **Scenario:** The Watch thought the user was asleep while they were reading in bed.
*   **Action:** User edits the "Wake Time" to ensure the RHR/HRV baseline is calculated from actual sleep, not wakefulness.

## 5. Subjective State (The Ground Truth)
*Calibrating the biological data with felt experience.*

### 5.1 The "Vibe Check"
*   **Scenario:** It's 2 PM, the post-lunch slump.
*   **Action:** User taps the "Check-In" button.
*   **Input:**
    *   **Energy:** ⚡️ Low
    *   **Focus:** ☁️ Foggy
    *   **Mood:** 😐 Neutral
*   **Outcome:** This data point is paired with the lunch meal (logged 1.5h ago) to train the "Brain Fog Forecast."

### 5.2 Symptom Tagging
*   **Scenario:** User feels heart palpitations after breakfast.
*   **Action:** User logs a specific symptom: **"Jittery"** or **"Heart Racing."**
*   **Outcome:** The engine checks this against the last meal + caffeine log to validate "The Caffeine Jitter" vs. "The Anxiety Mimic" (Hypoglycemia).

## 6. The Unified Timeline (The Dashboard)
*   **Scenario:** User scrolls through their day.
*   **Visual:** A single vertical timeline combining all events in chronological order:
    *   07:00 - Woke Up (Sleep Summary)
    *   07:30 - "Morning Stack" (Supplements)
    *   08:00 - Breakfast (Oatmeal)
    *   08:45 - *Subjective Log: "High Energy"*

    *   13:00 - Lunch (Chicken Salad) -> *Tagged "Refeed"*
*   **Value:** Visualizing the cause-and-effect flow of the day before any insights are even generated.

## 7. Edge Cases & Data Integrity (The "Unhappy Paths")
*Ensuring the system is robust against real-world friction.*

### 7.1 The "Fat Finger" Correction
*   **Scenario:** User accidentally taps the "Espresso" button three times because of lag or a slip.
*   **Gap:** Without correction, the "Caffeine Jitter" insight will trigger falsely.
*   **Action:** User swipes left on the timeline entry to "Delete" or "Edit."
*   **Outcome:** The data model updates immediately, removing the false spike prediction.

### 7.2 The "Frankenstein" Meal (Multi-Add)
*   **Scenario:** User eats a meal consisting of a Sandwich, an Apple, and a Coke.
*   **Gap:** Logging three separate events clogs the timeline and splits the "Glycemic Load."
*   **Action:** User adds items to a "Meal Cart" and taps **"Log Meal"** once.
*   **Outcome:** The engine aggregates the macros into a single "Meal Event" for accurate metabolic analysis.

### 7.3 The "Day 0" Empty State
*   **Scenario:** A new user lands on the dashboard. No meals, no workouts yet.
*   **Gap:** An empty white screen feels broken.
*   **Action:** Display a "Ghost Timeline" or a pulsing prompt: *"Your metabolic story starts with breakfast. Log your first meal."*

### 7.4 Historical Editing
*   **Scenario:** User forgets to log dinner and realizes it the next morning.
*   **Gap:** Logging it now would tag it as "Breakfast."
*   **Action:** User navigates back to "Yesterday" via a calendar view or changes the timestamp during logging.
*   **Outcome:** The engine correctly attributes the meal to the previous night's "Recovery Loop."

## 8. The Insight Loop (Outputs)
*Receiving value from the system: The "Cozy Coaching" moments.*

### 8.1 The "Sugar Spike" Alert (Acute Loop)
*   **Scenario:** User eats a donut at 3 PM. 40 minutes later, their heart rate spikes while sedentary.
*   **Visual Context:** The Mascot (Monch) appears in the Dynamic Island looking "Dizzy" (vibrating).
*   **Action:** User taps the notification: *"Heart rate velocity is high. A 10-minute walk now could flatten the curve."*
*   **Outcome:** User takes a walk. The "Spike" event is tagged as "Mitigated" on the timeline.

### 8.2 The "Kitchen Closing" Nudge (Circadian Loop)
*   **Scenario:** It is 8:00 PM. The user usually goes to bed at 11:00 PM.
*   **Visual Context:** Monch appears on the lock screen putting on pajamas.
*   **Copy:** *"Kitchen closing soon. Eating after 8 PM usually drops your Deep Sleep."*
*   **Outcome:** User decides against a late snack, preserving their "Digestion Debt."

### 8.3 The "Morning Review" (Retrospective)
*   **Scenario:** User wakes up with a low "Recovery Score."
*   **Visual Context:** The timeline shows a line connecting last night's "Late Pizza" log to the "Restless Sleep" block.
*   **Insight:** *"Your 10 PM meal kept your heart racing until 2 AM. Try eating 2 hours earlier tonight?"*
*   **Outcome:** User learns the specific biological cost of that specific meal.

### 8.4 The "Refeed" Validation (Anabolic Loop)
*   **Scenario:** User logs a large pasta meal after a heavy run.
*   **Visual Context:** Monch looks "Strong" (Flexing/Glowing).
*   **Insight:** *"Performance Fueling. Your muscles are soaking this up—no sugar crash expected."*
*   **Outcome:** User feels guilt-free about the carbs, reinforcing positive fueling behavior.

## 9. Summary Views (The Retrospective Lens)
*Stepping back from the river to see the landscape.*

### 9.1 The Day Summary
*   **Scenario:** User finishes logging dinner and wants to see how the day totaled up.
*   **Action:** User taps "Summary" or swipes left on the Timeline.
*   **Visual:** A compact view showing:
    *   **Macro Ring Chart** — Total Carbs/Fat/Protein filled in
    *   **Insight Badges** — Small icons for Sugar Spikes (coral), Refeeds (green), Debt (purple)
    *   **Sleep Preview** — If morning data exists
*   **Outcome:** User gets a "day in review" without scrolling the entire timeline.

### 9.2 The Week Summary
*   **Scenario:** It's Sunday. User wants to understand their weekly patterns.
*   **Action:** User navigates to Week view via a segmented control.
*   **Visual:**
    *   **7-Day Bar Chart** — Each day shows macro distribution stacked
    *   **Trend Arrows** — ↑↓ vs. previous week (Carbs down 12%, Protein up 8%)
    *   **Pattern Cards** — *"Late meals detected Fri/Sat"* or *"Refeed timing improved"*
*   **Outcome:** User spots behavioral patterns they wouldn't see day-by-day.

### 9.3 The Month Summary
*   **Scenario:** User wants to check progress over a longer horizon.
*   **Action:** User navigates to Month view.
*   **Visual:**
    *   **Calendar Heat Map** — Days colored by "metabolic quality" (green/yellow/red)
    *   **30-Day Streaks** — *"18 days without late-night eating"*
    *   **Chronic Insights** — Mineral Gap indicators, consistent patterns
*   **Outcome:** User sees long-term trends and streak motivation.

### 9.4 Empty State Handling
*   **Scenario:** User has only 3 days of data and taps Week Summary.
*   **Visual:** Partial chart with ghosted days + prompt: *"Keep logging—patterns emerge after 7 days."*
*   **Outcome:** Sets expectations without feeling broken.
